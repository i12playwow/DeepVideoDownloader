## Packaging gotchas
- electron-builder STRIPS `scripts` and `build` from the `package.json` baked into `app.asar`. They exist only on disk — never trust the asar copy.
- `build.asarUnpack: ["extension/**/*"]` is REQUIRED: `session.loadExtension` cannot load from inside asar, so the extension must be on a real path (`app.asar.unpacked/extension`).
- After bumping `package.json` `version`, rebuild + reinstall.

## Built-in browser = BrowserView (NOT <webview>)
`<webview>` (OOPIF) ignores its CSS box and renders at the 300×150 default (only ~top 1/5 of the page shows). `BrowserView.setBounds()` is deterministic — never revert to `<webview>`.
- Tab state lives in main.js: `bvAddTab`, `bvActivate`, `bvCloseTab`, `bvCloseTabForUrl`, `bvPositionActive`, `bvPushTabs`, `bvPushNav`.
- Renderer `browser.html` is pure UI: sends `bv-new-tab`/`bv-close`/`bv-activate`/`bv-navigate`/`bv-back`/`bv-forward`/`bv-reload`/`bv-content-rect` via `browser-preload.js` (`window.api`); listens for `browser-tabs-update`/`browser-nav-state`.
- BrowserViews share `session: browserSession()` = `persist:deepgrab-browser` (the session the extension loads into), so HLS detection works inside them.
- Finished-tab auto-close: `pushUpdate` → `bvCloseTabForUrl(item.referer || item.url)`.

- **How the extension grabs download URLs (3 independent layers → one `tryCapture`)**:
  1. **DOM scan (content.js)**: `scanVideoElements` (queries `<video src>`, `<source src*='.mp4'>`, `data-src/.mp4` attrs via `DEFAULT_VIDEO_SELECTORS`), `scanPageLinks` (any `<a href>` that matches), plus the supjav/sextb scanners (`scanSupjavList` → captures movie-*page* URLs as `kind:"link"`; `extractSupjav` → captures the `supjav.php?l=` player iframe). Periodic rescan re-runs for lazy-loaded content.
  2. **Network interception (content.js `hookNetwork`)**: wraps `XMLHttpRequest.open` + `window.fetch` (flags both the request URL and the post-redirect `resp.url`), and listens for `loadedmetadata`/`canplay`/`play` to read the `<video>` element's real `currentSrc`. Catches URLs the site never puts in the DOM.
  3. **webRequest (background.js)**: network-layer, works even in suspended/background tabs — `onBeforeRequest` flags any `NET_VIDEO_RE` (`\.(mp4|…|m3u8)`) or `ST_GETVIDEO_RE` (streamtape `get_video?`); `onHeadersReceived` fills `size` from `content-length`/`content-type`.
  - **Gate**: every URL passes `looksLikeVideoUrl()` (content.js:147) — media extension, streamtape `get_video`, or path with `/video/|/stream/|/media/|/playlist/`. `isAdUrl` always rejects ad hosts; `blob:` and non-http(s)/extension-scheme URLs dropped. All layers funnel into `tryCapture` → `found` list (size 0 → filled later by HEAD probe + status) → `video-found` → `maybeAutoDownload` → `sendToDesktop` → WS `download` → engine `enqueue`.

- **Appended-source auto-capture incl. links (2026-09-03, shipped 1.3.8)**: content.js's debounced top-frame MutationObserver already re-ran `scanVideoElements()` on DOM changes, so dynamically-appended `<video>`/`[data-src]` elements auto-captured — but appended `<a href=…mp4/m3u8>` LINKS only surfaced via `scanPageLinks()`, which ran on boot / Scan / `dv-rescan` but never in the observer or the 3s periodic scan. Exported for tests; harness section Q (bundled-wins / broken-explicit-falls-through / spawns / manager-cache).
