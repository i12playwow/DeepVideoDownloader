# AGENTS.md

Electron desktop downloader ("Deep Video Downloader") + companion Chrome MV3 extension ("Deep Grab") + supjav userscripts. CommonJS, no bundler, no build step for dev.

## Commands
- Run: `npm.cmd start` (never `npm` — PowerShell can't run `npm.ps1`). Do **not** use `run.bat` — it hardcodes the OneDrive copy path (launches stale code even from Desktop); `npm.cmd start` uses the current dir.
- Package: `npm.cmd run dist` → `dist/DeepVideoDownloader Setup 1.0.0.exe` + `dist/win-unpacked/`.
- No lint/test/typecheck. Syntax check: `node -c <file>.js` (extension JS included).

## Architecture
- `main.js` — Electron main: window, WS server (127.0.0.1:8765), IPC handlers, clipboard monitor, probe handler.
- `downloader.js` — download engine (segmented, queue, pause/resume/cancel, retry, **global** speed limit, scheduling, history) + site resolvers + HLS engine. History → `<downloadDir>\history.json` (moves with the dir), not the repo. For a **normal single download** a `done` item stays in the active map until dismissed, and `history.json` is only written on `remove(id)`. Under a **bulk/windowed import** (`addPending`) completed items **auto-move to history** (`_maybeFinalize`→`_toHistory`) so slots free for refill. Persistence (`history.json` + `downloaded.json`) is debounced ~500ms via `_persistSoon()`; `flush()` writes **synchronously** on quit so a debounced batch isn't lost on `taskkill /F`.
- **Bulk-scale (8/2026)**: `downloads-add-many` → `dm.addPending()` (windowed loader) keeps only a bounded live window (`config.liveWindow || concurrency*4`) materialized; completed items auto-move to history (`_toHistory`, cap `config.maxHistory` default 2000) to free slots. Duplicate handling: a `downloaded.json` set in the download dir records done URLs. `skipDuplicates` (default on) makes `enqueue` create a **`status:"duplicate"`** list row (not auto-downloaded) for already-downloaded URLs — re-download via `forceDownload(id)` ("Download anyway", IPC `downloads-force`); the bulk `refill` passes `markDuplicate:false` to skip dupes silently (no bloat), and `force:true` bypasses dedupe (`resumeLast` uses it). `saveHistory:false` disables writing `history.json`. Cloudflare/anti-bot: 429/`cf-chl`/`turnstile` classified as `rate-limited`/`blocked` (not dead), triggers proxy rotation (`markBad`) + backoff in `_runGuarded`, and `_paceHost()` enforces a per-host minimum interval. **Expired errors (403/404/410, `expired|token|forbidden`) also rotate the proxy** (`markBad` + clear `item._proxy`) before the refresh re-resolve — a CF-blocked proxy answering a bare 403 (no `cf-chl` text) would otherwise loop refreshing the same dead URL (added 8/2026). Config toggles (all in Advanced settings, applied at runtime via `dm.config`): `saveHistory`, `skipDuplicates`, `autoCloseTab`, `thumbnails`, plus `liveWindow`, `autoTrimAt`, `maxHistory`, `hostDelayMs`.
- **Multi-folder fallback (8/2026)**: `_activeDirSync()` picks `downloadDir` → `downloadDir2` → `downloadDir3` — the first folder whose drive has ≥ `minFreeMB` free (or the last one regardless); downloads **and** `history.json`/`downloaded.json` follow `dm.dir`, which can differ from `config.downloadDir` (`dm.dir` is a **getter** — recomputes free space and `mkdirSync`s on every access, so the active folder can shift mid-run). IPC `get-active-dir` (all 3 whitelist places) + renderer `#activeDir` "Saving to:" hint; **"Open folder" opens `dm.dir`, not `config.downloadDir`**. Keys `downloadDir2`/`downloadDir3`/`minFreeMB` in Advanced settings.
- `proxy.js` — `ProxyManager`; exports `parseProxyUrl`, `agentFor`, `transport`. `pickBest()` runs a **live latency test per call** (HEAD + GET fallback, 6s timeout) against the target for every configured proxy — with `autoProxy:true`, each download's probe/segments/resolver re-tests all proxies (that's why proxy latency shows up per download, not once).
- `preload.js` — `contextBridge` → `window.api`; the only renderer→main path (`contextIsolation:true`, `nodeIntegration:false`).
- `renderer.html/js/styles.css` — UI.
- **IPC whitelist**: every channel exists in 3 places that must stay in sync — `preload.js` (`window.api.<method>` mapping a method name to the channel string), `ipcMain.handle("<channel>")` in `main.js`, and call sites in `renderer.js`. **Renderer code only calls `window.api.<method>` — grepping renderer.js for the channel string finds nothing** (the string lives in preload.js), so renaming a channel touches preload.js (method + string), main.js, and every renderer call site.
- `config.json`: dev reads/writes at `__dirname` (gitignored); **packaged apps use `%APPDATA%\deep-video-downloader\config.json`** (`app.isPackaged` switch in main.js) so settings persist — never write into the read-only `app.asar`. `loadConfig()` strips a leading UTF-8 BOM (a Notepad/PowerShell save would otherwise make `JSON.parse` throw and silently reset to `DEFAULT_CONFIG`). Falls back to `DEFAULT_CONFIG` in main.js. `config - Copy.json` is a stale backup.
- **Built-in browser (added 8/2026)**: the app can open a tabbed browser window that runs the Deep Grab extension in its own Electron session (`persist:deepgrab-browser`), so videos are captured/downloaded without a separate Chrome. `main.js`: `loadBrowserExtension()` → `resolveExtensionDir()` (**`config.extensionPath` only if it contains `manifest.json`, else asar.unpacked (packaged) → `__dirname/extension` (dev); a stale `config.extensionPath` no longer silently disables the extension**), `createBrowserWindow()` (loads `browser.html` + `browser-preload.js`, `webviewTag:true`), IPC `browser-open`/`browser-nav`/`browser-external` (invoke) + main→browser `browser-get-tabs` and events `browser-open-tabs`/`browser-add-tabs`/`browser-close-tab-for-url`; the renderer URL textarea + target dropdown drive it. **Tabs are `<webview>` elements on the extension partition** — the extension's content scripts do inject into webviews (verified 8/2026). Multi-URL → one tab per URL; "Download all" hands the list to `downloads-add-many` → `addPending` (windowed). With `autoCloseTab` on, `main.js` `pushUpdate` sends `browser-close-tab-for-url` (matched by `item.referer`) on completion so the browser closes that tab + activates the next. **The extension must use `chrome.storage.local`, not `sync`** — Electron has no `storage.sync`, and content.js errors at init (no toolbar) if it references it. Only one extension per partition; reload the app after editing the extension. **Webview sizing**: OOPIF webviews don't follow `height:100%` inside flex containers (they sit at the 300×150 default) — `browser.html` uses `#content { flex: 1 1 0%; min-height: 0 }` plus a `ResizeObserver`/`resize` listener (`sizeWebviews()`) that forces explicit pixel width/height on every webview, and calls it again in `activate()` when a hidden tab is shown.
- **Ad bypass (8/2026)**: both `content.js` and `background.js` share an `AD_DOMAINS` regex; `isAdUrl()` skips ad-network streams so only real direct videos are captured (webRequest + DOM scan). Keep the two files identical between `extension/` and `extension-firefox/`.
- **One-click install (8/2026)**: "Install in browser" (`extension-install` IPC) launches Chrome/Edge/Brave with `--load-extension=<extensionDir>` + a dedicated `--user-data-dir=<userData>/browser-profile-<name>` + `chrome://extensions`. Chromium only honors `--load-extension` on a **non-default** profile, so this uses a persisted dedicated profile (extension stays loaded each launch; user's normal profile is untouched — no manual `chrome://extensions` load). `extensionDir()` mirrors `resolveExtensionDir()` precedence (validated `config.extensionPath` → asar.unpacked → `__dirname/extension`).
- `extension/` — self-contained MV3, not in `package.json`. Edit → **must reload at `chrome://extensions`**. `webRequest` + `*://*/*` perms, `all_frames:true`. Also loaded into the app's built-in browser session (see above).
- `extension-firefox/` — same JS as `extension/` (copied verbatim), Firefox manifest (event page + gecko id). **Ported 8/2026**: `webRequest` capture, cnporn extraction, pipeline, dedupe all in sync. Edit → **must reload at `about:debugging#/runtime/this-firefox`**. Load via "Load Temporary Add-on".
- Root `.user.js`/`test-*.js`/`test-page.html`/`test-video.mp4` are leftovers — see Userscripts + Verification.

## Download flow
Each `resolve*()` returns `{resolvedUrl, proxy, agent, origin?}` and re-resolves when the result is another supported site:
- `streamtape.com`/`fstape.com` → `resolveStreamtape` (`STRGV`) → signed `get_video?...&stream=1`. `get_video` returning `{"status":500}` means the video is dead source-side — not a resolver bug. **Since 8/2026 the modern streamtape embed no longer inlines `get_video` in the HTML** — the signed URL comes from a `/stat/<token>?a=0&rc=<recaptcha>` POST (gated by an ad-click + recaptcha + ~40s delay); the `rc` token is browser-generated, so a pure Node resolver can't get it (STRGV only matches legacy pages). **Modern streamtape must be captured via the built-in browser/extension**: the page JS runs recaptcha + the `/stat/` POST in the browser, and the extension's webRequest (`ST_GETVIDEO_RE`) intercepts the resulting `get_video` request.
- `cnporn.org` → `resolveCnPorn` (`CNIFRAME`/`CNIFRAME2`/`CNVIDEO` + `CNEMBED` for the lazy `/embed/<uuid>` iframe) → embed `sources` parsed by `CNSOURCES` (`"file":"...mp4|m3u8"`, JSON `\/` unescaped) → m3u8 (`origin:"cnporn-hls"`) or mp4 → streamtape/pornhub.
- `xvideos.com` → `resolveXVideos` (`XVEMBED`/`XVDIRECT`) → streamtape. `xhamster.com` → `resolveXHamster` (`XHEMBED`/`XHPLAY`/`XHMP4`) → xvideos → streamtape.
- `supjav.php?l=<OLID>` player URLs (supjav.com page 403s Cloudflare to Node, so resolution enters at the player) → `resolveSupjav` (`SJ_OLID`): reverse id → `?c=<reversed>` → 302s straight to the streamtape/fstape embed (`origin:"supjav-player"`) → `resolveStreamtape`. **Since 8/2026** supjav switched hosting to `turbovidhls.com/t/<id>` (JWPlayer/HLS): when the redirect lands there, `resolveSupjav` fetches the page and pulls the m3u8 from `#video_player[data-hash]` (a `cdn2.turboviplay.com/data1/<hex>/<hex>.m3u8` URL, `TVH_EMBED_RE`/`TVH_HASH_RE`, `origin:"supjav-turbovid-hls"`) → the HLS engine downloads it (same tiktokcdn segments + PNG-decoy as cnporn).
- Generic URLs pass through untouched. Resolved URL stored on `item._resolvedUrl` (used via `item._resolvedUrl || item.url`). Resolution is **lazy**: `enqueue()` returns an id immediately (WS `accepted` never blocks on a resolver fetch); pause/cancel during resolution aborts via the same post-async status check as the probe.
- **Per-host pacing (8/2026)**: `_paceHost()` keeps a minimum interval between requests to the same host (`config.hostDelayMs`, default 120) and is **serialized per host via `_paceChains`** — a naive timestamp check let concurrent callers read the same `last` time and burst together after a single cooldown; now each caller chains onto the previous caller's granted slot (which sets `_hostLast` before releasing). Threaded through the resolvers: `resolveUrl`/`resolveStreamtape`/`resolveSupjav`/`resolveCnPorn`/`resolveXVideos`/`resolveXHamster` take an optional `paceHost` (called before each page/redirect fetch; `_runOnce`/`_runGuarded` pass `(u) => this._paceHost(u)`), and `runHls` paces its playlist + variant fetches. `main.js probeUrl` stays unpaced (single-shot).
- Expired direct URLs (403/404/410 or `expired|token|forbidden`) auto-re-resolve up to `config.maxRefresh` (default 2), bumping `refreshCount`. A signed `get_video?` URL re-resolves from `item.referer` (the embed page — the only place a fresh expiry+token exists): `isSignedRefreshable`/`refreshSourceUrl`.
- **Thumbnails (8/2026)**: on `done`, `makeThumb()` extracts a 96px preview frame to `<finalPath>.thumb.jpg` with ffmpeg (`thumbnails:false` disables; silently skipped when ffmpeg is missing or extraction fails; existing thumb reused). `item.thumb` is exposed via `public()`/`listHistory`/WS `status` and the renderer shows a small `<img>` (file:// URL; `onerror` hides a stale path). Config toggle in Advanced → Behavior.
- **Resume last** (`↻ Resume last` → `download-resume-last` → `dm.resumeLast()`): re-queues the most recent `done`/`error`/`cancelled` item (else newest history entry) from its saved url/title/referer with `force:true` (so resuming a finished item re-downloads rather than creating a `duplicate` row) → fresh id; null when nothing to resume.
- **Engine hardening (8/2026)**: the dedupe-rename in `_runOnce` is gated on `item._pathCreated` (set after the check) so a pause→resume never orphans a `_<ts>.mp4` partial; `probe()` falls back HEAD→ranged GET when a server 405/501s HEAD (body destroyed, never written); proxy selection (`pickBest`/`agentFor`) uses `item._resolvedUrl || item.url` in probe/runSingle/downloadSegment so resolved URLs get matched against the proxy's host rules; a global segment-connection semaphore (`_withConnSlot`, limit = max of `concurrency`/`segments`) caps concurrent connections **across** all active downloads (a 3×4 run no longer opens 12); a segment getting HTTP 200 (server ignored Range) throws `category:"norange"` → `_runOnce` aborts, drops partials, and falls back to `runSingle` instead of merging truncated parts; **a terminal segment failure aborts sibling workers** (so they don't keep streaming into the temp dir while the item is retried/finalized — also trims the norange path); `runFfmpeg` **tracks the ffmpeg child in `_activeRes`** so `abort()` kills a mid-remux ffmpeg (`res.kill()`, not `.destroy()`, for ChildProcesses) instead of letting it finish; `resume()`/`forceDownload()` reset `lastEmit`/`_lastBytes` so the speed readout restarts cleanly.
- `sanitizeName()` **strips a trailing video extension** so callers can append `.mp4` — don't "simplify" it away or titles like `foo.mp4` become `foo.mp4.mp4` (fixed 8/2026).
- **Scheduling**: `scheduledStart` holds an item in `status:"scheduled"` until due; `scheduledStop` **pauses** a running/queued item once it passes (enforced 8/2026 — was display-only). `checkScheduled()` arms a sweep that wakes just before the nearest future start/stop (not a flat 30s), called from `enqueue`, the `download-schedule` IPC, **and `resume()`** (a paused scheduled-stop item could otherwise lose its sweep timer and never stop); an item whose **whole start..stop window already elapsed is paused instead of started**. Renderer `📅` prompts prefill **local-time** `YYYY-MM-DDTHH:MM` (UTC prefill would be off by the timezone offset).

## HLS downloads
`.m3u8` URLs get `item.kind:"hls"` at enqueue → `runHls()` (not probe/segmented): fetch playlist (paced via `_paceHost`) → pick best variant (`pickHlsVariant`: RESOLUTION then BANDWIDTH) → parse segments (`parseHlsPlaylist`; AES-128 `#EXT-X-KEY` → hard error, `.ts` only) → download **sequentially** via `downloadHlsSegment` (proxy failover, `_trackReq` abort, global speed limit). Resume skips existing `seg<N>.part`. Progress **indeterminate** (`total` stays 0). After the last segment `remuxToMp4` shells out to `ffmpeg` (`config.ffmpegPath`, default on PATH) with `-c copy -bsf:a aac_adtstoasc -movflags +faststart` → real `.mp4`.
- **Anti-bot decoy**: cnporn's and supjav/turbovidhls's segment CDN (tiktokcdn `.image` URLs) prepends a fake 1×1 PNG to each TS segment — `stripPngPrefix` trims up to the PNG `IEND` chunk, or ffmpeg muxes a garbage 1×1 png stream.
- The ffmpeg output is `<final>.part`, so pass `-f mp4` **immediately before** the output arg (ffmpeg can't infer the muxer from `.part`).
- Expired signed segments (403/410) bubble to `_runGuarded`; `isSignedRefreshable` covers `.m3u8` + `cnporn.org` referer → whole run re-resolves the cnporn page for a fresh playlist.

## WebSocket protocol (ws://127.0.0.1:8765)
- Server: `{type:"hello",version,port}` on connect; pushes `{type:"status",id,url,...,status,total,received,progress,speed}` on updates.
- Client→server:
  - `{type:"download",url,title,referer}` → `{type:"accepted",id,ids,url}` replied **immediately**, or `{type:"error",message,url}`. **Both `accepted` and `error` replies must echo `url`** — `background.js` matches `m.url === url` on each so concurrent sends can't mis-attribute a reply (regression fixed 8/2026; don't drop it).
  - `download` may carry `sources` (array of `{kind,url,label}`): enqueue every `kind:"link"` entry (label → `title[label].mp4`), fall back to plain `url` when none usable; `id` = first, `ids` = all. Non-`link` kinds (`iframe`/`server`) are player pages — ignored.
  - `{type:"ping"}`→`{type:"pong"}`; `{type:"probe",url}`→`{type:"probe-result",url,size,mime,ok}`.
- Extension: `background.js` is the WS client; `content.js` never talks WS — it uses `chrome.runtime` messages (`video-found`, `get-found`, `add-to-list`, `add-all-found`, `remove-found`, `desktop-status`, `open-new-tab`); background broadcasts `dv-found-updated`.
- `background.js` webRequest capture (`NET_VIDEO_RE` = `/\.(mp4|m4v|webm|mov|mkv|flv|m3u8)([?#]|$)/i` + `ST_GETVIDEO_RE` for streamtape/fstape `/get_video?`) catches videos in **suspended/background tabs** (no DOM). **Not retroactive** — only requests after the extension reload. `onHeadersReceived` fills `size`/`mime`.
- cnporn: lazy `/embed/<uuid>` iframe holds the mp4/m3u8 — `extractCnPorn()` (3s scan, Scan, `dv-rescan`) fetches each same-origin embed once (`resolvedEmbeds` dedupes), regexes `"file":"...mp4|m3u8"`. No play-click needed.
- Dedupe before send: `isDuplicate(url)` — exact URL in `captured`, or streamtape/fstape video id in persisted `capturedIds`. Duplicates: marked added, tab closed, nothing sent.
- `markCaptured` (on accepted) → `maybeCloseTab` auto-closes the tab — only streamtape/fstape `get_video` embeds, gated by `dv.autoCloseTab`. Failed sends leave the tab open.
- Pipeline (`▶ Start`/`■ Stop`, optional Qty limit): processes ST/FST tabs one-by-one — activate → signal `dv-autoplay-now` → content.js dispatches `deepgrab:autoplay` DOM event to the userscript → wait for accepted (or 25s timeout) → close → next. Autoplay is **gated behind that event**, so nothing plays until Start. **Pipeline state is persisted to `chrome.storage.local` (`dv_pipeline`) on every transition and restored on SW wake** (MV3 evicts idle service workers); `loadPersisted()` **merges** persisted found/captured instead of overwriting so a fresh capture landing during SW wake isn't clobbered. Dedupe is race-safe via a synchronous `pendingSend` Set (check-then-send no longer allows two concurrent sends of the same URL).
- Titles: ST/FST embed pages have generic `<title>`; `slugTitle()` derives names from the embed URL slug (content.js + background.js); app falls back to `titleFromReferer` at enqueue.

- `cancel()` **must remove the empty `finalPath`** it created mid-flight, not just `tempDir`, or a cancelled download leaves a 0-byte `.mp4` in the download dir (fixed 8/2026).

Successful HLS runs already clean their temp dir after remux; only interrupted runs leave them.
- Speed limit is **manager-wide** (`_speedBytes`/`_speedStart`), not per download.
- `new URL(p).origin` returns `"null"` for non-http(s) schemes — `parseProxyUrl` must use `u.href`. `ws://`/`wss://` rejected as proxy schemes. (The repo's `config.json` still lists `ws://127.0.0.1:8765` in `proxies` — harmless, it's the app's own WS port, parseProxyUrl just skips it.)

- Clipboard monitor only runs while `config.autoProxy` is true; `pornhub.com`/`javhub.net` in `VIDEO_DOMAINS` have **no resolver** (surface-only).
